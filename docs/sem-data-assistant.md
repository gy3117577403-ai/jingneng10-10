# 公司资料助手

入口：本机 8090 → 公司资料 → 资料助手。此批为 JN-0015，接续 JN-0014 的正文检索。

## 当前行为

用户选择暂不配置 API。默认“原文摘录”按关键词检索有权查看的发布版，并展示引用原文，不进行模型推理。“查询设置”中可指定分类、关键词和历史发布版；模拟测试需主动选择，界面及每个结果明确标记未调用模型。OpenAI 解读选项不可用；即使直接提交对应接口，也返回未接入提示，不悄悄改用模拟。

每个问题独立检索，不自动解析上一轮的“这个”“它”等指代。未填写关键词时只做有限的中文问句清理与字面匹配；需要更准确定位时填写关键词，多项用空格分隔。当前取最多八条匹配来源，不是语义检索或穷尽性总结。未找到来源、未完整提取正文、旧版来源分别提示，不编造答案。

会话仅本人可见；管理员的管理权限不开放他人的会话。会话最多五十个问题，达到上限后新建；会话列表每页二十项。归档保留历史并取消未结束查询，可恢复。每个会话同时处理一个问题，每人最多三个进行中的问题；提交使用请求标识去重。失败或取消可重试，反馈可标记有帮助或填写问题说明。

## 权限与引用

- 原资料权限仍是唯一依据。默认检索当前发布版本；历史版需要显式选择，草稿不参与。限时授权仅开放被批准的版本。
- 每次处理、完成交付、读取历史时重新检查当前账号及资料权限。任一所用来源不可访问时，整个相关回答、引用和检索摘要隐藏，防止组合回答残留部分机密。
- 每条来源保存记录、版本、文件、页码或工作表行号；点击来源前再次读取会话，原文接口继续独立鉴权。阅读不自动授予下载或编辑权限。
- 新发布版不覆盖历史引用，旧回答会提示来源已有新版。文件哈希或正文索引引用失效时隐藏旧回答，重新提问即可按当前来源查找。
- 界面在重新聚焦、重新进入及轮询时核对权限，失败时清空原回答。已经交付给用户、被复制或截屏的内容不能远程撤回。
- 来源内的命令、脚本或提示均作为文本展示；不调用 SQL、业务写入工具或外部链接。查询、反馈、归档等只修改助手自身记录，不创建或批准业务单据。

## 预留模型契约

实现位置为 `app/Services/CompanyData/Assistant`。`AnswerProvider` 是内部可替换契约，`OpenAiReservedProvider` 当前明确拒绝运行，无 HTTP 客户端、密钥读取或隐含外发。

输入契约 `company-data-answer/v1`：本次问题及已授权来源快照（局部编号、标题、版本、位置、正文、定位摘录）。不把用户凭据、数据库接口、原件路径、旧轮回答或业务工具交给提供者。

输出为 `paragraphs[{text,citations[{source_id,quote}]}]`。每段必须有引用；来源编号必须来自本次输入，摘录必须真实存在于对应原文；无效结构或伪造引用整次拒绝。此结构校验不等于验证未来模型的所有推断正确性，真实接入时仍需单独做内容质量、注入干扰及无依据拒答评测。

本批的摘录与模拟提供者都不使用网络。后续真实接入须由用户恢复 API 配置，完成供应商配置、传输与错误处理、费用控制和实际模型验收；本批不宣称这些已经完成。

## 运行与恢复

新增 `jn_data_conversations` / `jn_data_answers` 两表，随数据库备份保存。正文及原件继续由已有资料模块保存。查询使用持久状态、独占执行凭证、事务后派发；队列丢失或处理超过三分钟由 `jingneng:recover-answers` 每分钟恢复，连续三次中断后保留失败，等待人工重试。取消或新执行凭证会使迟到结果失效。

可通过运行环境 `COMPANY_DATA_ASSISTANT_DEMO=false` 关闭新模拟请求；默认允许显式选择的离线测试。无需模型凭据。测试覆盖归档恢复、并发去重、跨账号隔离、引用伪造、权限撤销、借阅过期、取消竞态和中断恢复；真实 HTTP 脚本为 `scripts/sem_assistant_acceptance.py`。准确执行结果见 JN-0015 更新记录。

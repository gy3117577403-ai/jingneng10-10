# 报价工作台（JN-0023）

入口为 `/zh-CN/quotation-workspace`，从「销售与客户 → 报价 → 报价工作台」进入。原报价页也有工作台入口。JN-0022 的 5181 独立预览继续保留；8090 页面连接实际数据库，不使用浏览器 localStorage 或预览虚构种子数据。

## 操作流程

1. 新建报价：选择已启用的客户档案、该客户联系人和地址、既有付款与交付条件，填写项目和成套/钣金分类。新建后立即生成现有 `quotes` 表中的草稿，不发送客户通知。
2. 添加明细：新建产品，填写图号、规格、材料、表面处理，选择系统单位和税率；或者从历史报价的详情抽屉复用。报价数量与单价保留系统支持的三位小数。旧折扣、说明行、技术详情和附件不会被新页面整体替换。
3. 维护成本：在「成本核价」逐项添加或调整名称、用量、规格、单位、价格与来源。没有价格显示「待核价」，不是零成本。价格依据确认后，再确认本次数量和配置。修改相关字段后取消本次核对标记。
4. 保存：点击「保存报价」，服务器成功后显示已保存。返回列表或查找历史前先保存；失败留在编辑页面并保留输入。刷新/关闭浏览器时对未保存修改触发浏览器离开提醒。页面不将浏览器临时状态称为数据库保存。
5. 历史查询：查询现有报价明细，可搜索项目、客户、编号、产品、图号、材质与规格，按业务或成本核对状态筛选；列表有服务端分页。详情抽屉保留原价格和当前报价条件。历史中的草稿/已发送/已成交等状态来自原报价，不将人工成本核对当作正式审核。
6. 复用：可加入可编辑草稿，也可建立新报价。服务器重新检查源报价版本，复制明细及已有技术关系，保存来源快照；所有成本依据和本次配置需要重新核对。不建立或复制售前询价的资料访问授权。
7. 保存记录：每次保存保留报价及成本快照，详情展示最近 50 次，可查当时的产品、价格及依据。「保存 V」是工作台存档次数，与正式审核版本、图纸版本不同。

## 一致性和权限

- 使用原有 `quotes`、`quote_lines`，增量表 `jn_quote_workspaces` 存分类与逐行成本，`jn_quote_workspace_versions` 留不可变快照；现有 `jn_sales_receipts` 保证重试幂等。保存采用父报价事务锁和整体内容指纹，同时检测原报价编辑器产生的变更。
- 复用在稳定顺序的父报价锁内执行，重新检查来源权限与指纹。来源价格和成本修改不会反向改变目标快照。失败重试不会重复创建明细；新建目标成功但来源已过期时，界面保留已建立的目标，避免重试再建一份。
- 遵循现有账号启用、组织关联和 `quotes-menu` 权限；管理员可访问全部，普通账号仅自己的报价。当前不开放销售互相读取内部成本，也不自动扩权；跨销售共享库的精细授权需后续明确配置。
- 新工作台对已结束、核对中、当前版本已通过审核、使用工艺自动计价的报价只读。原报价及打印入口继续保留。订单转换、技术交接与正式审核沿用既有模块，不以本次保存触发。
- 正式审核快照包含工作台成本及存档版本；原先无工作台数据的审核快照结构不变。原报价更新数量、价格、折扣或单位后，已核对标记失效。
- 删除与工艺、附件或订单关联的产品明细需要在原报价流程处理；工作台拒绝整次保存，防止断开关联。页面移除在保存前可撤销。

## 范围边界

本批打通现有系统内的报价数据闭环。销售电脑、聊天或 Excel 中的历史文件尚未自动导入；成本是逐份报价的版本化依据，尚不是统一供应商实时价目库。本批不建立自动算价规则，不接通供应商接口，不修改生产环境。

## 验证与运行

新增后端测试 `JingnengQuotationWorkspaceTest` 覆盖保存、历史、权限、重复提交、过期版本、复用隔离、非法数据回滚、小数数量和原说明行保留。前端 `QuotationWorkspace.test.jsx` 覆盖实际请求、冲突保留输入、登录失效、金额和展开核价。实际浏览器验收、配套备份恢复与运行镜像证据见 [JN-0023](changes/JN-0023.md)。

恢复需配套数据库、文件与配置。回退界面可切回上一个镜像并保留两张新增表；回退代码不删除新报价数据。不要在已使用工作台后直接回滚迁移删除存档。需要回到升级前数据时，先备份当前状态并核对升级后新增记录，再从配套备份恢复。

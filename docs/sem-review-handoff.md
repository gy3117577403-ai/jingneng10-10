# 报价核对与技术交接（JN-0012）

入口为本机 `http://127.0.0.1:8090`。复用既有报价和订单，新增版本核对、固定 PDF 和技术资料交接。成套、钣金共用同一条流程。首次试用使用明确标识的虚构资料；企业正式审批规则、工程有效版本、BOM 和生产放行另行适配。

## 从报价到交接

1. 按 [销售关联说明](sem-sales.md) 从询价生成报价草稿，人工录入产品、数量、价格和交期。
2. 在报价上方点“提交核对”。选核对人和本次共享的资料，查看报价内容，填写说明并勾选确认。每份资料只能选一个当前版本；文件不存在或摘要不符会阻止提交。
3. 核对人在“待我处理”打开报价核对。可确认或退回修改；销售也可以撤回待核对版本。退回后修改并重新提交会生成新版本，原版本、意见和文件保留。
4. 确认时保存固定中文 PDF。历史下载读取已保存文件；修改原报价不会改变旧 PDF。原报价的“文档”入口在当前版本已确认时也下载该文件，否则明确显示未确认草稿。
5. 选择报价产品行并点“创建订单”。从售前生成或已经进入版本核对的报价，须当前版本已确认且资料没有变化。订单记录所依据的报价版本及选中明细。
6. 在订单上方点“发起交接”，选择技术接收人、期望完成日期、本次资料和可编辑核对项，填写说明并确认共享。
7. 技术接收人从待办打开交接，接收、要求补充或退回。补充文件后由发起人重新交接，形成新版本。完成前必须逐项勾选核对要求，并填写处理意见。

接收和完成都会重新核对订单与原件是否变化。交接完成只记录本次技术资料交接，不修改订单的生产完成状态。转单后的补充资料可以与报价确认时的原件不同，两份依据分别保留。

## 岗位和记录权限

| 身份 | 本批可执行的动作 |
| --- | --- |
| 销售：`Sales` 角色或相应权限 | 本人负责的报价提交/撤回，订单交接/补充/撤回 |
| 报价核对员 | 查看明确分配给自己的报价版本、所共享原件和固定 PDF，处理待核对版本 |
| 技术接收员 | 查看当前明确分配给自己的交接、版本原件和处理记录，接收、补充请求、退回、完成 |
| 管理员 | 管理和演示操作；演示允许同一管理员提交并确认，普通人员须由另一人核对 |

新增四项权限为“提交报价核对”“核对报价版本”“发起技术交接”“接收技术交接”。可以用现有角色管理配置；本批不推定企业完整组织审批矩阵。演示角色账号只在本机验收时生成，不写入公开种子或固定密码。

记录的负责人身份与操作权限同时检查。禁用或撤销相应权限后不能继续操作或下载。更换订单接收人后，旧接收人不再通过交接访问记录；更换销售负责人后，旧负责人的“我发起的”也不再显示它。报价的历史核对人保留对曾明确分配给自己的版本的访问，除非撤销核对权限。

提交时明确共享所选原件，不会自动把整个询价授权给核对人或技术接收人。报价快照仅共享报价相关客户、联系人、地址和商业配置，不复制客户内部备注或会计账户。原询价自身仍按其原来的记录权限访问。

## 交互与一致性

- 状态与下一步放在原报价、订单上方，历史按需展开；独立核对页面可从待办进入，不要求核对人员获得原报价编辑权限。
- 右侧表单显示本次依据，底部操作持续可见，窄屏表格在自身范围滚动。修改后的关闭提示使用软件内窗口；失败保留输入，提交中防止重复点击。
- 同一内容重试使用同一请求标识。服务端持久回执仍先复核当前权限；同一标识换内容或换人员会报冲突。
- 标准报价/订单编辑与本批处理共用父记录事务锁，核对来源时同时锁定询价。过期页面提交、并发处理、资料更新均须重新核对。
- 待办新增“报价核对”“技术交接”，按当前待处理岗位、发起记录与授权范围筛选，抑制对应原业务的重复待办。

历史独立 ERP 报价未进入本流程时沿用原功能。旧订单没有报价确认版本关系时不能直接发起本批交接，不能靠补一个状态声称已有确认依据。本批覆盖现有主信息、明细编辑与 JSON 转单路径，不宣称所有上游模块、导入器、第三方 API 都已纳入同一审批体系。当前 AI 仍为固定标签模拟。

# 当前方向与进度

记录日期：2026-10-10（北京时间）。本页为可公开的接续摘要，具体版本状态以 Git、对应更新记录及验收报告为准。

## 已确认方向

- 为定制制造企业建立协作软件与 AI 辅助能力，ERP 是其中受控执行的一部分。
- 新系统重建，旧资料通过上传整理，不以旧软件 API 对接为前置工作。
- 结构化记录、原始文件、版本与来源一起管理。先建能运行的框架，真实字段逐步补齐。
- 首期成套、钣金两类演示场景同步验证，不连接正式生产。
- 用户确认方案和必要配置，助手执行获准范围内的搭建、接口、测试和交付。
- 指定远端 gy3117577403-ai/jingneng10-10 为后续提交目标，更新编号、分支、提交和 PR 明确关联，不重复实现或覆盖历史。
- 先为本企业内部落地；以开源能力为基础，参考商业软件解决实际问题的方法，对外产品化后续评估。具体候选模块仍需验收后确定。

## 当前实现路线

用户在 JN-0006 后确认提速：优先引入 WebErpMesv2 完整开源应用，再进行企业适配和 AI 扩展。JN-0007 在 `apps/sem` 固定引入提交 `6cd15090949f0a66ea28380c7e0751ab63aea94c`（MIT），使用 Laravel 12 / PHP 8.3.35、MariaDB、Redis、Docker Compose，独立入口 8090。运行与迁移见 [ΣEM 说明](sem.md)，实际验收状态见 [JN-0007](changes/JN-0007.md)。这是完整开源应用的本机试用，不等于全模块企业验收或生产切换。

JN-0008 在 ΣEM 中重新实现售前询价、私有原件版本、来源快照、模拟提取、人工确认和留痕，见 [售前说明](sem-presales.md)。采用负责人/管理员/指定协作者的记录级访问控制。JN-0011 增加客户关联、人工确认后生成报价草稿及沿用原功能转订单，见 [销售关联说明](sem-sales.md)。当前仍是固定标签模拟，企业正式计价与审批规则未适配。

以下为保留的 Frappe 基线，入口仍是 8088；其业务数据与 UI 没有迁移，两边没有数据同步。

采用 Frappe 16.51.0 独立自定义应用，MariaDB 11.8.9、Redis 7.4.11、Docker Compose。源码在 `apps/jingneng`，当前尚未安装 ERPNext 模块，未修改 Frappe 核心。F1 前端使用 Vue 3.5.43 / Frappe UI 1.0.0，依赖锁文件随源码提交。

F0 已有登录、9 个部门、两类演示种子、服务与后台队列检查及配套备份。F1 增加工作台、询价/产品行、私有原件的不可覆盖版本、持久协作任务、活动记录与快照 ZIP。F2 增加模拟提取、持久运行、来源快照与人工候选审核；按用户选择暂不接入真实模型。任务由人工分派、回复和确认，不能把 F0 短期缓存中的环境检查当业务任务，也不能把 F1 人工协作当模型推理。

演示销售能创建本人负责的询价并分派/确认任务，技术只进入被指定的记录参与协作。部门目录不会自动授权整个部门；全企业岗位权限矩阵尚未适配。详细动作、限制和使用方法见 [工作台说明](workbench.md)。

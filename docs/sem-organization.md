# 组织、成员与授权工作区

本模块从 JN-0018 开始提供，沿用现有 ΣEM 登录及数据库。入口为本机 `http://127.0.0.1:8090/organization`，也可从工作台导航进入“组织与成员”。这是组织管理及资料授权的基础，不替代企业正式的人事确认、业务审批或其他 ERP 模块的岗位规则。

## 日常操作

- 左侧组织目录可搜索、展开和收起；选中组织后，右侧架构图、面包屑及成员列表切换到对应范围。
- 架构图支持平移、缩放、适应画布、展开分支和显示成员。每个分支先显示六条成员记录，更多记录通过“查看全部”进入完整列表。
- 桌面点击人物打开固定资料面板，可继续切换人物，查看基本资料、任职关系和账号状态。较窄桌面减少上级图形节点，完整路径仍在面包屑和任职详情中。
- 手机默认进入成员列表，目录按需展开；长表格可在表格内横向滚动。编辑表单内部滚动，取消和保存固定在底部。
- 顶部搜索覆盖当前有权查看的组织、姓名和职务；按 `/` 可聚焦搜索。表单未保存时关闭会出现软件内确认窗口。

## 添加、修改与删除

组织分为公司、部门、车间、班组和项目。项目类型与部门类型分开，但均可拥有成员和下级节点。资料分类目录不决定组织的隶属关系。

组织编辑包含名称、类型、上级、排序、状态及备注。服务端拒绝循环关系、超过十二层、同层重名或越出授权范围的调整。有下级、当前任职、组织授权或资料权限引用时，不能直接删除或停用，须先处理引用；不级联删除人员。

成员可新增、编辑、停用、删除，并配置一个主职及多个兼任。姓名允许重复，成员编号唯一。任职调整保留结束的历史关系；删除成员保留历史记录和原登录账号，但关联账号不能继续访问受检的组织、资料和应用工作区。当前总管理员关联的成员和账号不能直接删除或停用，须先转交管理员。

岗位可以独立维护。正在使用的岗位不能删除或停用；先调整任职，避免成员后续编辑受阻。

头像支持本人 JPG、PNG 或 WebP，最大 5 MB，源图尺寸为 64 至 6000 像素。界面可调整取景和缩放，服务端重新编码为 512×512 的私有图片，读取需要成员查看权限。没有照片时显示姓名占位。仓库中的五张头像属于虚构演示人物，不会自动关联实际员工。

保存支持重复请求去重及版本冲突检查。多人同时编辑时，旧版本提交会被拒绝，当前表单内容保留，需核对最新记录后重试。删除不是清除所有历史，也不提供本批未实现的回收站界面；需要恢复时应依据配套备份处理。

## 总管理员与责任人交接

初始化时只指定一个现有在用管理员为组织总管理员。原账号和密码保留，凭据仍在本机忽略目录 `.local/sem/credentials.txt`；不写入仓库，也不自动发给其他人。

组织总管理员可维护组织、成员、岗位、角色、授权、账号关联及头像。其他账号即使在旧系统带有 Admin 角色，也不会自动取得组织总管理员权限。转交管理员需要当前账号密码、有效接任账号及当前配置版本，成功后旧管理员立即失去组织总管理员身份。

预置角色仅提供配置模板，初始化不会分配给员工：

| 角色 | 默认能力 |
| --- | --- |
| 组织只读 | 查看授权范围的组织和成员 |
| 成员维护 | 查看、维护成员与任职、头像、联系方式 |
| 部门维护 | 成员维护能力，以及维护组织、查看变更记录 |

角色可以调整。授权需要选择账号、角色、组织范围、是否包含下级及到期时间。岗位维护属于全局能力，只有全公司范围授权生效。角色不包含授予他人权限或转交总管理员的能力。

跨部门兼任人员的修改需要覆盖其全部当前任职范围；只具有部分范围查看权的账号只会看到相应关系，不能借此修改另一部门的任职。联系方式另有权限。撤销、到期、角色停用或成员停用在下一次服务端请求重新判断，已经打开的页面不构成继续操作的授权。

建议的实际交接顺序：核对成员身份和任职 → 关联或创建独立登录账号 → 选择角色及负责组织 → 配置必要的资料权限 → 用责任人账号验收。创建成员不会自动创建账号；待核对或停用人员不能开通账号，账号创建后也不会自动得到组织授权。

## 与公司资料的衔接

组织管理权和资料内容权限分别设置。资料中心原有的查看、编辑、审核、下载、导出及协作等动作继续受原权限规则约束，新增两个授权对象：

- **组织直属成员**：只匹配该组织当前任职且已关联账号的成员。
- **组织及下级成员**：匹配该组织及其当前下级组织的成员。

明确拒绝仍优先。组织移动会改变“含下级”范围，因此移动前应核对当前责任范围和资料授权。总管理员身份不自动绕过资料内容规则；现有资料管理入口仍沿用既有管理角色。部门主管标记、钉钉管理员标签、资料文件夹名称均不会自动授予软件权限。

## 导入与留痕

服务器命令 `php artisan organization:initialize --owner=<现有管理员邮箱> --file=<私有规范化JSON>` 只供本机初始化和受控导入使用。固定导入标识用于去重，与可编辑成员编号分开；修改成员编号后重复导入也不会新增重复记录或覆盖人工编辑。私有人员导入默认待核对，不根据重名自动合并，也不自动创建登录账号。未知上级、循环或超过十二层会使整次导入回滚。

`--demo` 仅用于隔离的虚构演示环境，不能和私有文件导入同时使用。界面数量来自当前记录：存在待核对资料时显示“条记录”，不能当作已经核实的员工总人数。

组织、任职、头像、角色、授权和管理员变更写入审计表，界面显示最近可见的一百条记录。密码不写入审计内容。内部截图、导入文件、验收图片、上传文件、运行数据库及配置均留在 `.local` 或私有存储中，不进入公开 GitHub。

## 运行与恢复

本批新增九张 `jn_org_*` 表。更新前后均使用应用数据库、文件及配置的配套备份，不复制 Docker 虚拟磁盘。备份检查除文件哈希和表行数外，新增九张组织表的内容哈希，用于核对管理员、任职、角色和授权恢复的一致性。

正常更新使用 `python scripts/sem.py start`；备份使用 `python scripts/sem.py backup`；隔离恢复使用 `python scripts/sem.py restore-check --backup <目录>`。恢复检查端口 8091 应空闲，检查通过后只清理该次隔离项目。

代码回退不等于资料回退。不要直接删除新表或执行清空迁移；保留配套备份，先在隔离环境恢复并核对，再决定是否替换本机运行实例。旧 JN-0017 不能解释新增组织授权，不能把切换旧镜像当作完整权限回退。

本批未启用实际责任人账号、未代定正式权限矩阵、未切换生产环境。头像收集、同名身份确认、实际岗位标准化和正式部门责任范围仍需企业核对。

## JN-0020 界面与连续操作

组织和成员已在8090接入实际shadcn/Base UI控件与公共视觉层；本节更新外观和操作连续性，不改上述组织、身份和授权规则。

- 组织图每个父节点共享一条主干；节点与连线同时过渡，连续展开/收起可打断前一次动画。保持选中和缩放，只有主动“适应画布”才重新全图适配。首次进入兼顾可读字号，较大组织可平移查看。
- 打开成员资料保留图形上下文，在可用画布中显示选中节点；右侧面板提供原有基本资料、任职关系和账号权限。切换到成员页后选中行仍有反馈，主操作对应当前视图。
- 状态选择器、成员显示开关和组织操作菜单使用实际组件，支持键盘和焦点恢复；新增/编辑仍沿用原有接口、校验、版本冲突和未保存保护。真实数据未因本批视觉测试被修改。
- 组织页与工作台使用相同的全局导航、查找和账号入口；标题左侧可独立收起组织目录，标题右侧管理菜单保留岗位、权限与记录入口。操作根据原有权限展示。
- 初始架构图以100%显示，点击缩放百分比可恢复可读尺寸；点击适应画布可查看全图。较窄窗口可收起目录或平移，避免强制缩小字体。新增/编辑中的长组织与岗位列表支持输入搜索，选择后才改变字段值。
- 390px窄屏的组织搜索、成员列表和资料底部操作已实测；主视图随原有窄屏规则进入成员列表。减少动态效果设置下不播放布局移动。

验证、旧镜像回退和配套恢复记录见 [JN-0020](changes/JN-0020.md)。内部人员截图保存在本机忽略目录，公开仓库只包含通用实现和脱敏验证结论。

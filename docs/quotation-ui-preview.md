# 销售报价交互方案与真实组件预览

工作编号：JN-0022。当前是独立前端交互预览，使用虚构客户、价格、文件索引和本机演示状态。未接入8090业务、实际历史报价、供应商价格、企业审核或正式输出。

## 设计目标

销售的主任务是找到可参考明细，理解本次差异，补齐成本依据并完成报价核对。成套包括柜体、电气元件、辅材、装配和调试；钣金包括材料、加工及表面处理。沿用京能品牌蓝和系统无衬线字体，用列表、细分隔线和右侧核价面板表达工作关系。

默认预览为桌面工作区。正文与主要控件12–13px，辅助信息10–11px，主标题18–22px；历史明细双行约61–69px，工作台双行约66px。按钮7px圆角、输入6px、独立概览12px。主要文字#232b37，辅助文字#596d87，背景#f5f6f8，内容表面白色，强调#1967d2，待处理#96621f。主色白字对比度约5.37:1，辅助色在主背景约4.90:1；这是选定颜色对检查，不是全量无障碍认证。

真实使用现有[shadcn/ui Base UI按钮](https://ui.shadcn.com/docs/components/base/button)、输入、Select、Checkbox、Tabs、Dialog、Textarea和Table，历史排序使用[TanStack与shadcn组合方式](https://ui.shadcn.com/docs/components/base/data-table)。[Motion](https://motion.dev/docs/react-animation)负责轻按、页面过渡、成本折叠。未额外混入另一套控件皮肤；HeroUI、Ant Design、Aceternity、Magic UI没有作为本批运行依赖。

## 页面与交互

| 页面 | 信息层级 | 操作 |
| --- | --- | --- |
| 报价工作台 | 待处理数量、项目列表、所选报价的下一步 | 按项目或客户查询、成套/钣金筛选、状态页签、新建、继续报价 |
| 历史报价 | 可检索产品明细、历史条件、右侧成本及来源 | 多关键词组合搜索、类型/核实状态筛选、五列排序、选择详情、折叠成本、复用 |
| 报价编辑 | 产品与对外价格、内部成本、右侧本次核价 | 数量/单价编辑、成本展开、补价与来源确认、移除和撤销、核对、报价单预览、创建修订 |

桌面：`导航 / 明细工作区 / 上下文或核价面板`。窄屏：保留报价工作台与历史导航，列表可横向滚动，详情按纵向排列，弹窗独立滚动。

历史报价不可被草稿编辑覆盖。复用时复制成本对象并清除确认状态；数量、单价或成本变化后需重新核对。缺失成本保留空值，不按零计价。金额以分为单位汇总。演示核对要求有明细、有效数量和价格、成本及依据已确认。完成后版本只读；创建修订保留原记录。客户视图只展示对外明细，不展示内部成本。

历史文件只是虚构来源索引，没有伪造可下载的Excel/PDF或图纸内容。当前没有Excel导入、真实审批、发给客户、固定正式PDF、客户接受、转订单、字段权限或官方计价规则。这些需在后续接入时沿用现有业务能力并独立验证。

## 体验路径

入口：<http://127.0.0.1:5181/quotes?view=workbench>。

1. 打开“装配车间配电改造”，查看8台柜体的报价草稿，展开柜体、元件、辅材、装配及调试。
2. 直接点“核对报价”，界面会列出缺价/依据/配置待确认，不能完成演示核对。
3. 在右侧电气元件输入演示价格和来源，再勾选该项依据与本次数量配置。再次核对可完成演示状态。
4. 打开报价单预览，核对客户视图没有内部成本。创建修订后原版本仍留在工作台。
5. 到历史报价输入“远川 2.0”，选择钣金与已核实，定位立式设备机柜。复用到新草稿或已有同类草稿，原历史保持不变。
6. 改数量、单价或依据时，之前的明细确认清除。移除明细后可以撤销；刷新保留本机演示内容。
7. 左下角重置按钮可恢复初始报价演示；不会清理组织演示或8090数据。

专用本地存储键：`jingneng.quotation-ui-preview.v1`。关闭页面或刷新仍保留，但不是服务器保存或业务备份。浏览器存储不可写时显示失败提示。

## 设计取舍与后续

本轮优先验证查找、复用和核价，价格依据嵌入所选明细，不单独建空白管理首页。未来价格维护可从当前来源入口进入。成套引用钣金柜体核价、历史Excel整理、企业字段和计价规则需要真实样本，不能用演示值替代。

预览确认后，按现有客户、询价、报价、版本核对与订单模型逐步接入8090；单独验证权限、并发、持久化、导入和原件可追溯性。独立预览结果不代表业务模块已上线。

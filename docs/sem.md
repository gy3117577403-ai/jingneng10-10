## 验收与边界

验收记录以 [JN-0007](changes/JN-0007.md) 与本机 `.local/acceptance/jn-0007/` 的实际结果为准。本说明中的操作路径不代表全部功能均已通过验收。

```powershell

```

完整验收会生成虚构业务记录；只读选项只检查登录、配置与模块入口。后端测试必须在 SQLite 内存库运行，不能把 PHPUnit 的刷新数据库机制指向当前演示库。

## 数据与恢复

```powershell
python scripts/sem.py backup
python scripts/sem.py restore-check --backup .local/sem/backups/<时间戳>
```

备份会短暂停止本演示的写入服务，配套导出数据库、上传文件及配置，生成 SHA-256 清单后恢复服务。`APP_KEY` 是加密字段的恢复条件，必须与数据库一起保存。

恢复检查只创建带时间戳的新测试项目，使用 8091 和独立网段/卷；实际导入备份后核对业务行数、文件摘要与登录。通过后清理该临时恢复项目，失败则停止并保留以便调查。备份成功不等于恢复成功，以恢复报告为准。

迁往另一台电脑时，需要源码/当前分支、Docker、`.local/sem` 配置和配套备份。只克隆 Git 不会恢复密码、上传文件、数据库或完整聊天。本机备份不是异地备份。

本机已执行独立恢复演练：恢复后 19 张关键业务表的行数、备份中的全部文件摘要及登录匹配；原始 SQL 备份覆盖整库，不只导出这 19 张表。该演练运行在同一台电脑的独立容器中；新电脑的实际启动仍需按交付包 README 复验。

```powershell
# 工作区提交后，生成包含源码、Git 历史、运行镜像和配套备份的私密目录
python scripts/sem.py package
# 新电脑按包内 README 放置配置、加载 images.tar 后恢复
python scripts/sem.py restore-new --backup .local/sem/transfer
```

迁移包位于 `.local/sem/releases/`，含真实本机密码与 APP_KEY，不能推到公开仓库。`restore-new` 拒绝覆盖任何同名容器或数据卷。`history.bundle` 保存已存在的分支历史；`source.zip` 是固定提交的源码。该包不包含旧 Frappe 数据、企业内部原件或完整聊天。

如镜像/依赖下载慢，可在本机 `.local/sem/compose.env` 配置 `SEM_DEBIAN_MIRROR` 与 `SEM_NPM_REGISTRY`；仍保留 APT 签名与 NPM 锁文件完整性校验。默认使用官方源。本批不更改全局 Docker 或其他项目的网络配置。

当前网络发生过 HTTP/2 截断，本机额外使用 `SEM_COMPOSER_HTTP1=1`：仅在构建时让 Composer 使用 HTTP/1.1，继续验证 TLS、沿用原始依赖锁文件。缓存和有限重试避免重复下载；此开关默认关闭。

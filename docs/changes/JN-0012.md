## 目标与范围

用户授权完成报价版本核对、固定版本中文文件、订单技术交接及最小岗位权限与待办。依赖尚未合并的 PR #10，复用现有 ΣEM 报价、计算、PDF 和工作收件箱；成套、钣金分别验收。暂不做换电脑迁移、真实模型、工程有效版本/BOM/生产放行。本批完成后准备公司数据库接入模块方案，实际数据来源与连接方式待明确，不连接未知公司数据库。

## 具体变化

1. 报价新增提交、指定核对人、确认、退回和撤回；每次保存完整内容及明确共享的资料版本。修改后重新核对产生新版本，旧意见和原件可追溯。
2. 提交时冻结打印 HTML 和草稿 PDF，确认时由冻结内容生成中文确认 PDF，后续下载不重新套用变动中的报价。保存并校验文件 SHA-256，原报价打印入口区分确认文件与未确认草稿。
3. 从售前产生或已经进入核对的报价，必须确认当前版本才能沿现有 JSON 明细接口转单；订单保存确认版本和明细关系。原报价/订单主信息及明细编辑与核对使用同一父记录事务锁。
4. 订单新增指定接收人、期限、选定原件及核对项的技术交接。支持接收、要求补充、退回、补充后重新交接、逐项确认完成、撤回；重新提交保留版本历史，交接不修改生产完成状态。
5. 增加四项操作权限及核对/技术接收角色，按负责人和明确分配记录授权。禁用人员不进入候选列表，重新分配及权限撤销后旧访问失效；报价历史核对人保留被分配版本访问。共享报价必要字段，不复制客户内部备注和会计账户。
6. 共用工作收件箱新增报价核对与技术交接；独立处理页供相应岗位使用。紧凑状态区、按需历史、右侧操作窗口、失败输入保留、变更关闭提示、重复提交锁及请求回执；过期依据和并发状态变化均返回冲突。
7. 开工运行环境出现数据库连接耗尽，定位到定时器每分钟启动默认常驻的 `pulse:check`。改为启用监控时执行 `pulse:check --once` 并防重叠，重启清除累积进程后服务恢复。回归测试保留该条件，不把短期观察等同长期容量验证。
8. 增加真实 HTTP 双类型核对交接验收及 CI 步骤；连续测试达到既有请求频率限制时按 `Retry-After` 等待，保持原请求标识，不放宽应用限流。备份检查补齐来源、核对、交接和事件表计数。

使用说明见 [报价与交接](../sem-review-handoff.md)。本批完成后准备的 [公司数据中心方案](../architecture/company-data-module.md) 是独立下一模块提案，未实现或接入正式数据库。

## 目标与范围

用户要求先设计销售报价交互方案并提供可操作预览。沿用现有独立组件预览，聚焦成套/钣金历史明细查询、复用、差异核价与确认呈现。依赖开工时未合并的 PR #20。使用明确虚构资料；本批不接入8090报价业务、真实价格或数据库，不部署生产。

## 具体变化

1. 在现有 `apps/ui-preview` 增加独立 `/quotes` 入口及延迟加载，原组织与成员预览保留。复用已安装的 shadcn/ui Base UI、TanStack Table、Motion 与 Lucide，没有新增依赖。
2. 报价工作台以单一列表提供查询、成套/钣金筛选、状态页签、新建及每行下一步，直接打开报价。历史报价提供唯一搜索框、已核实筛选、五列双向排序；详情按需打开，固定底部复用到新草稿或已有同类草稿。
3. 报价编辑分为共用数据的「报价明细」与「成本核价」。数量/单价在明细维护，成本价格/来源只在核价页维护，一次展开一项，确认后进入下一项。保留核对阻断、对外报价单、只读演示版本、创建修订、移除及不覆盖其余修改的撤销。
4. 演示规则区分未知成本与零值；复制历史明细时独立复制成本并清除核对状态。数量、单价、配置或成本变化会要求重新确认。对外预览不显示内部成本。
5. 银白工作区、紧凑系统字体及细分隔线明确层级，移除常驻右侧核价面板与重复成本列表。规格和成本描述提升到12px，主要控件13px；按钮轻按、成本连续折叠、减少动态效果与透明度适配保留。窄屏报价明细纵向排列，历史表格只在自身容器内滚动。
6. 新增8条虚构历史明细及4份虚构初始草稿，来源文件仅为索引示例，不提供伪造原件。报价演示状态保存在独立浏览器本地存储，支持重置及保存失败提示。
7. 设计依据、布局、组件选择、体验路径和接入边界见 `docs/quotation-ui-preview.md`。修复主入口热更新时重复创建React root的清理问题。

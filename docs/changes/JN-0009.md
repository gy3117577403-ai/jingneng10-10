## 目标与范围

用户要求整套软件 UI 和交互沿用之前的设计，并明确先完成上一批再改 UI。JN-0008 已完成本机验收、提交、远端同步、PR #7 与迁移包校验后，单独开始本任务；开工时仍在运行的 PR #7 CI 随后已核实全部通过。两批分别留档，不把功能收尾与界面工作混作一个编号。

在实际 ΣEM 应用统一导航、页面、列表、表单、弹窗、登录与主要业务页面。依据 `docs/ui-workspace.md`：紧凑、全中文、减少无效空白和技术噪声，采用冷白、中性灰、石墨文字和蓝色强调，短动效与减少动态效果设置。保留现有模块、权限及正式写入校验，不创建另一套静态替身。

## 具体变化

- 公共布局统一为 204 px 导航、56 px 顶栏、中文系统字体、紧凑表单与表格、克制的蓝色强调。重新设计首页、登录页、弹窗、菜单和移动端入口；公共组件使已有模块沿用同一视觉。未把每个上游专用业务页面都重写成另一套实现。
- 原菜单按七个工作分组收纳；保留原入口、权限条件、动态订单数量与当前页面定位。手机菜单支持多层入口，修复嵌套分组后重复订单入口的问题。页面查找只从当前账号过滤后的菜单生成，支持 Ctrl/Command + K、方向键、Enter 和 Escape。
- 首页使用现有数据库的询价、订单、报价与指标，默认工作概览，保留今日事项和分析看板。查询失败可重试、空数据明确提示。首页视图与紧凑/舒适密度保存在当前浏览器。
- 共用列表默认进入列表视图，筛选和列设置按需展开，保留列显隐与排序记忆。明确标注“本页筛选”，不暗示能够筛选未加载记录。表头支持键盘排序。
- 报价和订单详情收起审核/变更的次要字段，已有内容或校验错误时展开。修改后点击页面链接离开会弹出应用内确认，取消保留输入。原保存接口、权限与服务端校验继续生效。
- 将现有原生确认调用改成需要 await 的应用内确认框；覆盖 React 删除/锁定/转换等操作和 Blade 表单。取消不写入，重复确认不排队重放，保留原表单提交按钮及浏览器校验。
- 售前审核完成后优先展示确认回执，候选与来源可展开查阅；待核对状态继续直接展示候选。未配置模型时隐藏全局聊天入口，售前仍明确标为模拟测试。
- 中文工作区统一浅色与深色两种主题，旧“专业”偏好映射为浅色。移除远程字体请求，主要详情页 jQuery 改用随软件打包的本地资源。
- 浏览器检查发现质量空数据仍显示外部占比 100%，已修复为“暂无数据”；有记录时继续按真实分布计算。补齐订单明细及报价复制/模板反馈的中文文案。收紧 1024 px 布局，登录页移除与登录无关的版本信息。
- 镜像、验收输出和迁移包编号改为 JN-0009；原 JN-0008 包保留。操作说明见 [工作区界面与交互](../sem-ui.md)。

## 剩余事项

- 原生确认框替换不等于上游所有写入操作都已增加新审核流程，服务端业务规则仍由原模块控制。
- 页面内未保存提示仅覆盖已标记的报价/订单表单及页面链接，浏览器关闭、手动改网址等外部动作不在覆盖范围；React 编辑器保留各自的草稿逻辑。
- 100 个入口可达不等于每个上游业务动作都完成企业验收。正式岗位权限、国内财税、真实订单规则需后续逐项确认。
- JN-0008 的真实模型识别、正式转报价、工程有效版本规则、跨电脑实际恢复及生产部署保持未完成状态；不将虚构验收数据包装成真实经营效果。

## 目标与范围

用户最新确认暂不配置 API，先预留接口并完成其他功能。本批接续 JN-0014 的正文检索，提供个人会话、受权限约束的来源摘录、显式模拟测试、固定版本引用、异步状态及恢复、反馈与交互。OpenAI 只预留可替换契约，不创建密钥、不请求外部模型，不把摘录或模拟描述为真实 AI 推理。

## 具体变化

公司资料增加“资料助手”：默认原文摘录、显式模拟模式、查询分类/关键词/历史版、私有会话与归档恢复、反馈、取消及重试。引用固定到查询时的记录、版本、文件、页码或工作表位置；点击直接打开原文。沿用紧凑中文工作区，设置按需展开、桌面提问区固定、手机内容区域内部滚动，保留未提交问题的切换确认。

持久查询状态、事务后派发、独占执行凭证及定时恢复，避免重复提交和迟到结果覆盖取消。每次检索、结果交付及历史读取重新鉴权；任一来源失效时整个回答与引用隐藏。会话仅本人可见，管理员不自动获得他人历史。分类不是组织，助手不新增业务写入能力，不绕过原有内容权限。

预留 `company-data-answer/v1` 和 `AnswerProvider`：只传入已授权来源快照，逐段校验来源编号及原文引用。OpenAI 适配器没有 HTTP 或密钥读取，明确拒绝未接入请求，界面不将模拟伪装成模型推理。接口边界与现有能力限制见 [使用说明](../sem-data-assistant.md)。

运行、备份检查和 CI 接入新模块。停用账号的 JSON 请求返回中文拒绝信息；登录重定向不再导致空响应崩溃。完整测试中应用路由循环引用达到原512MB限制，增加测试结束后的垃圾回收，未扩大内存或跳过测试。

真实回归中出现一次原报价核对并发插入的 MariaDB 1020 错误。补充仅针对此错误的最多三次完整事务重试，每次重新核对权限与幂等记录，并清理失败尝试生成的 PDF；持续冲突仍抛错。故障注入验证单次冲突后只有一个核对版本、回执和 PDF，持续冲突受限且不残留 PDF。

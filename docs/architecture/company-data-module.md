# 公司数据中心：下一模块方案

状态：JN-0012 阶段历史方案，保留后续主数据导入和连接器方向。2026-10-11，用户已授权 JN-0013 先完成通用资料与台账、权限、协同和文件导入，实际实现范围与边界见 [公司资料使用说明](../sem-company-data.md)；下文的映射模板、错误清单导出、主数据更正合并等仍是后续建议，不能当作全部已实现。未连接正式公司数据库。

## 先明确接入含义

用户已确认的方向是重建软件、旧数据上传，结构化记录与文件资料一起管理。此次“把公司的数据库接进去”尚未明确是导入旧库导出文件、只读连接仍运行的数据库，还是建立公司的统一资料库。按先前约定，首选导入方案；连接器仅预留，等来源、范围和用途确认后再实现。

公司资料能够查询，不等于已经能正确驱动报价或生产。第一版先建立来源、对应关系和可核对的数据，再将明确批准的字段写入现有业务对象。AI 分析继续使用现有模拟能力，真实模型另行配置与评测。

## 使用后的样子

导航新增“公司数据中心”，主要提供四个工作页面：

| 页面 | 员工看到并完成的操作 |
| --- | --- |
| 数据概览 | 查看本部门可访问的记录和文件，搜索客户、项目、物料或编号，进入关联详情 |
| 导入任务 | 上传表格或结构化导出文件，选字段对应关系，先预览，再修正和确认导入 |
| 记录详情 | 在同一处查看标准字段、历史来源、关联报价/订单、原始附件与文件版本 |
| 待处理问题 | 处理缺少编号、格式不符、疑似重复、附件无法匹配和关联对象不存在等具体问题 |

沿用当前紧凑表格、右侧详情、按需展开历史和中文状态，不把数据库连接串、SQL、任务堆栈或内部调试日志放入员工日常页面。必要的连接配置集中在管理员设置，密码只在服务器私有配置中保存。

## 首批实现建议

第一阶段先用一类表格和一组关联文件跑通，建议客户或物料二选一；不一次导入全公司。样本可以先用脱敏或虚构数据。各部门是权限和管理范围，不默认每个部门都新建独立数据库；跨部门共用的客户、物料和单据保留稳定标识。

处理链为：上传原件 → 临时区解析 → 字段映射 → 格式及关联检查 → 疑似重复比较 → 人工确认 → 按批次入库 → 记录与文件可追溯。

| 能力 | 第一版应具备的行为 |
| --- | --- |
| 来源登记 | 每批保存来源名称、文件摘要、导入人、时间、源行号及规则版本 |
| 字段映射 | 中文列名对应标准字段，可保存模板；保留原值，不默默猜单位、编号或日期 |
| 校验 | 区分阻止导入的错误与需确认的提示；下载具体错误清单；可先修正再提交 |
| 去重 | 用稳定来源键/业务编号和批次摘要防重复；同名不同客户不自动合并；冲突显示双方差异 |
| 附件关联 | 依据明确编号或人工选择关联文件；保存原件及版本；匹配不明时放入待确认列表 |
| 确认入库 | 未确认只存在临时区；明确展示新增、更新、跳过和错误数量；后台失败可重试且不重复写入 |
| 权限和审计 | 按部门、岗位及记录范围控制列表、搜索、下载和导入；敏感资料单独授权 |
| 更正与撤销 | 保留批次内写入前后值和后续引用；无后续变更时可撤销本批，有引用或新编辑时生成补偿更正，不能直接删除关联业务 |

先复用 ΣEM 现有客户、物料等主数据。只有未建模的来源记录进入受控来源表，不另造一套与业务主数据无关联的“公司真相库”。原始文件保存在私有文件存储，数据库记录其版本、摘要、权限和关联关系；需要全文检索时再加索引，搜索索引不是原始依据。

## 只读数据库连接分支

若用户选择仍运行数据库的只读连接，则先确认数据库种类/版本、可连网络、指定表或只读视图、字段含义、稳定主键、更新时间和允许读取范围。第一版只抓取批准范围到临时区，再走同一套校验和确认，不让模型直接执行任意 SQL，也不使用源库管理账号。

连接器应有超时、单次读取量和并发限制，配置通过服务器私有环境提供；只读账号的实际权限要验证。增量同步还需明确删除标记、时间字段可靠性和数据冲突处理。没有稳定主键或增量标记时先用受控全量快照，不把简单定时查询称为可靠双向同步。

数据库原始备份文件不可直接当作在线系统导入脚本执行；若以后需要处理，应先在隔离环境恢复并导出批准的数据。源库结构不能未经映射直接覆盖当前业务库结构。

## 开始实施前需要确认

1. 接入方式：上传 Excel/CSV 等导出文件、只读连库，或以新资料库为主。
2. 首批数据对象、字段样本和数量级；哪个编号唯一、字段含义、单位、时间格式及更新规律。
3. 文件在哪里、如何与记录对应，是否已有编号和版本规则。
4. 谁可看、谁可导入确认，是否涉及报价成本、人事、财务等需要单独授权的信息。
5. 本地演示或正式环境、备份位置、可接受导入时间；数据库地址和密钥通过本机私有配置提供，不贴进聊天或公开仓库。

其中第 1 项尚待用户回答，其余可在模块实施前用一份脱敏样本逐项确认。现阶段没有凭据、正式数据或连接地址，不声称已接通。

## 验收标准

- 同一批数据反复上传或任务重试不产生重复正式记录；同名但不同编号的数据不被误合并。
- 缺少必填字段、单位歧义、重复编号和错误附件关联能够定位到源文件/源行，并阻止相应记录直接入库。
- 未确认数据不污染现有客户、物料、报价或订单；确认后能从业务记录回到原始依据。
- 文件新版本、源数据更新和人工更正都有历史，旧报价/交接依据保持不变。
- 无权限人员不能从搜索、详情、下载或后台接口绕过记录限制。
- 在隔离环境恢复配套数据库与文件备份，并验证记录数、关联关系和原件摘要；备份文件存在不等于恢复可用。

接入整家公司各部门、双向实时同步、自动主数据合并、真实 AI 自动归类和正式生产写入不列入首个导入试点，后续按实际验证结果扩展。
